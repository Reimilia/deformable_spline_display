# Deformation Lab implementation

The frontend is `app/index.html` plus `app/src/multilink/`. The original
Three.js racket application is preserved at `app/racket.html`.
`server.py` serves the built app and two API operations:

- `GET /api/checkpoints`: the registry, display labels, stage, family,
  conditioning type, default integration settings and task-set sizes.
- `POST /api/rollout`: a selected checkpoint, optional comparison, task set,
  task index and numerical/physical overrides. The response contains actual
  rollout geometry, phase coordinates/momenta and aligned diagnostics.

The service binds to localhost by default. `python run_demo.py --port 8766`
changes its port. If developing with Vite on a different backend port, update
the proxy in `app/vite.config.js` accordingly.

The repository also supports static deployment through
[`../../GITHUB_PAGES.md`](../../GITHUB_PAGES.md) and
`.github/workflows/pages.yml`. `export_previews.py` generates server-free
checkpoint playback data into `../data/previews`. Static comparisons are
restricted to stages of the same variant and verified to share a saved initial
state and target. Connect a separate HTTPS service for live recomputation.
`server.py --allow-origin https://YOUR-USERNAME.github.io` enables cross-origin
API use and handles OPTIONS preflight requests for that origin.

## Checkpoint inventory

The registry discovers trained model files under `vendor/outputs`. It contains:

- **18 articulated checkpoints**: open, hard holonomic and FIM closure variants,
  each with pretrain, shape and pose snapshots, shape-only final, positioned
  final, and hard-transfer model.
- **40 spline checkpoints**: open and periodic variants plus FIM tolerances
  0.02, 0.05 and 0.10; both configuration and observation conditioning. Each
  variant has pretrained, stage-1, final and hard-transfer weights.

Cached task files are used for scenario selection and are excluded from the
dynamics dropdown. The complete original model files are bundled unchanged,
including optimizer state in resume snapshots. Snapshot options load
`model_state` exactly as saved; final/transfer options load `state_dict`.
Architecture and chain metadata missing from a snapshot/transfer checkpoint
come from its own run's `model.pt`. Snapshot options do not silently substitute
the checkpoint's separate `best_state` field.

## Integration and meanings

`engine.py` calls the supplied `rollout_world_pose_info_ph` and
`rollout_spline_ph` implementations in `vendor/multilink_ph`. It does not replace
their forces or integration with a JavaScript approximation. No training occurs
in the demo. Each request reconstructs a model and copies the cached task;
subsequent requests cannot inherit changed parameters or task offsets.

- Command duration is 1 normalized time unit. **Steps per command** sets
  `dt=1/steps`; the evaluation horizon extends the settling interval while
  clamping reference progress at one.
- **Learned damping** multiplies learned damping parameters. For articulated
  dynamics this scales the learned extra joint damping; baseline environmental
  drag and baseline joint damping retain their saved values.
- **Learned stiffness** multiplies learned positive stiffness parameters.
  The original model's positivity clamps still apply.
- **FIM tolerance** overrides the primary model's saved closure tolerance. In
  articulated variants it is relative to perimeter; in spline variants it is
  the saved spline closure tolerance. It is shown only for FIM variants.
- **FIM damping** is the articulated integrator's actual `use_fim_damping`
  switch. Spline variants retain their supplied seam-force implementation.
- **FIM** is the requested display name for the original `measurement` closure
  mode. This rename does not turn spline measurement closure into a new Fisher
  matrix model. Internal serialization keys and checkpoint paths retain their
  original names for compatibility.
- **Observation noise** changes the spline target point cloud with a seeded
  Gaussian perturbation. It affects observation conditioning and the saved OT
  force when enabled. Configuration conditioning retains its explicit target
  configuration. Noise changes the sensing input; it does not add process noise.
- Shape remains the exact saved initial/target intrinsic configuration. Pose
  controls change global initial orientation and global target pose. Spline
  observations are transformed consistently with the target-pose change.
- Pretrain, shape-only and articulated hard-transfer weights receive the
  original shape-only conditioning. Pose snapshots and positioned final models
  receive the relative target pose. Global pose is generated by articulated
  inertia and environmental dissipation; the demo adds no direct pose actuator.

## Rendering and diagnostics

All panels reuse the racket app's `Playback` time cursor. Geometry retains its
aspect ratio and can show the explicit global SE(2) placement or intrinsic body
frame. The renderer draws the generated curve/link vertices as supplied and
does not invent a closing edge at an open seam. Initial shape, fitted target,
learned moving reference, target observation points and pose trail can be
inspected. Energy/metric samples are aligned with step endpoints. There is no
fabricated energy value at time zero for spline rollouts.

The phase selector covers control-point coordinates, knot logits and pose for
splines, and joint angles and pose for articulated systems. Joint coordinates
use their corresponding generalized momenta. Articulated pose channels plot
world coordinates against body momenta; these mixed-frame channels are labeled
explicitly and are diagnostic views rather than a canonical global chart.

Shape RMS is the material-indexed body-frame RMS against the saved fitted
representation, with no Procrustes registration. Pose error is translation
norm. Generalized speed uses the full native generalized velocity. The spline
Sinkhorn diagnostic and articulated balance residual/FIM trace are available
only when the respective integrator produces them. Moving-reference work can
increase H, so energy decrease is not used as a universal success condition.

The fitted target and the target point cloud can differ, particularly for hard
OOD tasks; showing target points exposes that representation limit. Selecting
a different task retains its exact saved target fit. The app does not refit or
claim convergence beyond the behavior of the supplied checkpoints.

## Overlay contract

Both runs start from separate copies of the primary selection's exact saved
task. They receive the same pose offsets, horizon, step count and learned
stiffness/damping multipliers. Spline observation noise uses the same seed.
The second checkpoint retains its own closure mode, conditioning type, trained
closure tolerance and articulated FIM switch. The two targets are drawn
separately if their sampled representations differ. Overlay comparisons across
the articulated/spline families are rejected because their state spaces and
physical scales differ. Comparisons changing conditioning or closure evaluate
the model on the primary task's saved representation, which may differ from
its own training distribution.

## Contents and provenance

`vendor/multilink_ph` and `vendor/outputs` were copied from the attached
`multilink_ph_locomotion_with_results.zip`. All 74 supplied `.pt` files are
included; 58 contain selectable model weights, and 16 contain task caches.
The original multilink archive is unchanged. The original LieSPHGP sources,
tests, frozen Python racket reference and architecture notes are preserved.
Historical racket-only architecture notes are supplemented by this document.
