# Racket Viz

This repository now defaults to **Deformation Lab**, a checkpoint-backed
multilink/spline explorer. From the repository root run `python run_demo.py`
after installing `multilink_backend/requirements.txt`. The prebuilt app is
included. See [the backend notes](multilink_backend/README.md).

The original racket demo described below is preserved at `/racket.html`.
For frontend development Vite still serves both pages; the new deformation
page also needs the Python checkpoint service running on port 8765.

Interactive four-panel visualization of the Dzhanibekov effect / tennis racket
theorem: a torque-free (and optionally controlled, and optionally wind-
disturbed) rigid body, rendered as (1) the racket in 3D, (2) its angular-
momentum trajectory on the Casimir sphere, (3) angular velocity vs. time, and
(4) current-vs-desired state under active control. A sidebar lets you change
the racket's geometry/mass, starting/ending spin axis, control on/off, and
wind on/off, then "Run" to see the result — computed live, in the browser.

See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the data contract and design, and
[`DECISIONS.md`](DECISIONS.md) for the dated log of why things are built the
way they are.

## Layout

- `app/` — Vite + Three.js. This is the whole running app.
  - `app/src/physics/` — the physics engine, in JavaScript, run entirely
    client-side. Given the sidebar's parameters, computes the racket's
    inertia tensor, integrates a trajectory (free/controlled/windy), and
    builds the Casimir-sphere phase portrait — all live, no server.
  - `app/src/scenes/`, `app/src/core/` — rendering (Three.js scenes, 2D canvas
    panels) and playback (a single time cursor driving all four panels).
  - `app/src/main.js` — wires the sidebar to the physics engine to the
    renderer.
- `physics/` — Python. The **frozen reference implementation** the JS engine
  above was ported from and is cross-validated against (shared fixtures in
  `physics/tests/fixtures/`, read by both `pytest` and the JS test suite). Not
  in the running app's runtime path at all anymore; `physics/export.py` can
  still generate standalone scenario JSON if that's ever useful.
- `data/` — JSON generated by `physics/export.py` (gitignored). Not used by
  the running app; a small hand-authored sample for the JS tests lives in
  `app/src/test/fixtures/sample_scenario.json` instead.

## Status

Feature-complete for "physically accurate and parameterizable": all four
panels work, the sidebar drives a live client-side physics engine (no
precomputed data needed), and a first round of hands-on UI feedback has been
addressed. Not yet done: a real visual design/styling pass (currently plain
sliders and borders, no labels-and-polish treatment) — deliberately deferred
until the simulation itself was verified correct.

## Running

```bash
cd app && npm install   # first time only
npm run dev
```

Then open the printed local URL (typically `http://localhost:5173`) in a
browser.

### Using the app

- It loads with a default scenario already running.
- **Presets** (top of sidebar) one-click into the four original demo
  scenarios — filling in the sliders below and running immediately.
- **Racket geometry** sliders reshape the racket live as you drag them (no
  need to hit Run to see the shape change).
- **Motion**: starting axis, duration, a **Control** toggle (reveals an
  ending axis once on), and a **Wind** toggle (reveals a strength slider once
  on).
- **Run** rebuilds and plays whatever combination is currently set.
- **Play/Pause** (top left) controls playback of whatever's currently loaded;
  once a run finishes it becomes "Replay."
- **Hamiltonian 3D** (top-right corner of the Casimir sphere panel, off by
  default) overlays the energy-level ellipsoid the sphere-panel curves are
  the intersection of.

## Testing

```bash
cd app && npm test           # JS: physics engine + rendering-logic unit tests
cd physics && pytest         # Python: the reference implementation's own tests
```

Both suites are independent of each other and of the running app — the
Python suite doesn't need Node, the JS suite doesn't need Python.
